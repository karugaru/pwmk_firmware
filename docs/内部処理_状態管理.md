# 状態管理

## 概要

状態管理は、キーボードの現在の動作状態と、短時間だけ利用者へ知らせる状態を管理します。
LEDの色、点滅パターン、表示時間は状態管理では決めず、ペリフェラル処理が状態を表示へ変換します。

この分離により、状態の遷移とLEDの見せ方を別々に変更できます。
状態管理は「何が起きているか」を保持し、ペリフェラル層は「どのように知らせるか」を担当します。

状態は次の3種類の情報から構成されます。

- 定常状態: 起動、初期化、接続待機、接続済み、スリープなど、現在の動作を表します。
- 一時状態: 設定保存やVialアンロックなど、短時間だけ利用者へ通知する結果や進行状況を表します。
- 接続優先設定: USBとBLEのどちらを優先して待機または接続するかを表します。

定常状態と一時状態は、それぞれ最大1件だけ保持します。一時状態にはキューがなく、
新しい一時状態を設定すると、以前の一時状態が置き換えられます。

## 状態の種類

### 定常状態

定常状態は、システムの動作を継続的に表します。
定常状態を直接変更するAPIはなく、移行先を要求してから周期処理で適用します。

定常状態には、次の状態があります。

| 状態                          | 意味                                                                   |
| ----------------------------- | ---------------------------------------------------------------------- |
| `STATE_BOOTING`               | メイン処理を開始し、起動処理を実行している。                           |
| `STATE_SYS_INIT`              | 基本ペリフェラル、設定、キーマトリクス、入力処理などを初期化している。 |
| `STATE_BLE_INIT`              | BLE機能を初期化している。BLE有効時だけ使用する。                       |
| `STATE_INIT_COMPLETE`         | すべての初期化が完了し、通信状態へ移行できる。                         |
| `STATE_USB_WAITING`           | USB接続を待機している。                                                |
| `STATE_BLE_WAITING`           | BLE接続を待機している。BLE広告中を含む。                               |
| `STATE_BLE_CONNECTED`         | BLEが接続されている。                                                  |
| `STATE_USB_CONNECTED`         | USBデバイスがマウントされている。                                      |
| `STATE_BOOTLOADER`            | ブートローダーへの移行が要求された。                                   |
| `STATE_DEEP_SLEEP`            | ディープスリープへ移行する。                                           |
| `STATE_INIT_ERROR_PERIPHERAL` | 周辺機器の初期化に失敗した。                                           |
| `STATE_INIT_ERROR_BLE`        | BLEの初期化に失敗した。                                                |
| `STATE_INIT_ERROR_SETTINGS`   | 設定の初期化に失敗した。                                               |

### 一時状態

一時状態は、定常状態を変更せずに、短時間の処理や操作結果を通知します。
定常状態と同時に保持でき、表示時にはペリフェラル層が一時状態を優先します。

| 状態                             | 意味                                             |
| -------------------------------- | ------------------------------------------------ |
| `STATE_TEMP_NONE`                | 一時状態がない。                                 |
| `STATE_TEMP_SETTINGS_SAVING`     | 設定を永続化領域へ保存している。                 |
| `STATE_TEMP_SETTINGS_PERSISTED`  | 設定がRAMと永続化領域へ反映された。              |
| `STATE_TEMP_SETTINGS_RAM_ONLY`   | 設定はRAMへ反映されたが、永続化できなかった。    |
| `STATE_TEMP_SETTINGS_FAILED`     | 設定を反映できなかった。                         |
| `STATE_TEMP_VIAL_UNLOCKING`      | Vialアンロック操作を受け付け、完了を待っている。 |
| `STATE_TEMP_VIAL_UNLOCKED`       | Vialのアンロックが完了した。                     |
| `STATE_TEMP_VIAL_LOCKED`         | Vialがロック中のため、操作を拒否した。           |
| `STATE_TEMP_CONNECTION_SWITCHED` | 接続優先設定の切り替えを受け付けた。             |
| `STATE_TEMP_BLE_SLOT_CHANGED`    | BLEスロットの変更を受け付けた。                  |

一時状態の設定とクリアは状態管理が行いますが、表示期限は状態管理が保持しません。
ペリフェラル層が表示開始時刻を記録し、規定時間が過ぎたときに `state_clear_temporary_state()`
を呼び出して定常状態の表示へ戻します。

### 接続優先設定

接続優先設定には `CONN_PREF_USB` と `CONN_PREF_BLE` があります。
この設定は接続先を強制するものではなく、USBとBLEのどちらも接続されていないときの
待機先や接続試行先を選ぶために使います。

接続済み状態の判定にも接続優先設定を使用します。
`CONN_PREF_USB` の場合はUSBを先に判定し、USBがなければBLEを判定します。
`CONN_PREF_BLE` の場合はBLEを先に判定し、BLEがなければUSBを判定します。
どちらも接続されていない場合も、接続優先設定に対応する待機状態になります。

そのため、USBとBLEが同時に利用可能な場合は、接続優先設定によって現在の接続済み状態が変わります。
これは、USBがマウントされていれば常にUSB接続済みとする仕様とは異なります。

## 状態の保持と遷移

状態管理は、次の値を内部に保持します。

- 現在の定常状態
- 現在の一時状態
- 要求された定常状態
- 接続優先設定

定常状態を変更する処理は、次の2段階で行います。

1. 呼び出し元が `state_request_steady_state()` で移行先を要求する。
2. 周期処理が `state_process_periodic()` を実行し、要求を現在の定常状態へ反映する。

定常状態の要求が適用された周期では、接続状況からのランタイム状態の解決は行いません。
次の周期以降、現在の定常状態がランタイム状態または初期化完了状態であれば、
USBのマウント状態、BLEの接続状態、接続優先設定から現在の状態を解決します。

この仕組みにより、初期化中の状態がUSBやBLEの状態によって上書きされることを防ぎます。
初期化完了後は、接続状況の変化を周期処理で反映できます。

定常状態の遷移に伴う特殊な処理は、状態管理から要求します。

- `STATE_DEEP_SLEEP` への遷移時は、スリープ処理へ移行します。
- `STATE_BOOTLOADER` への遷移時は、ペリフェラル処理が白色点灯を出力した後、ブートローダーへ移行します。

## 周期処理

状態管理とペリフェラル表示は、メイン処理の周期処理から呼び出されます。
BLE有効時はCYW43のasync contextから、BLE無効時はメインループから周期処理が実行されます。

状態管理の周期処理は、次の順番で動作します。

1. 要求された定常状態があれば、現在の定常状態へ適用する。
2. ランタイム状態または初期化完了状態なら、接続状況から次の定常状態を解決する。
3. 状態の遷移に必要な特殊処理があれば実行する。

ペリフェラルの周期処理は、状態管理の後に実行されます。
通常は現在の定常状態と一時状態を読み取り、LEDへ出力します。

一時状態の表示中に定常状態が変更された場合、ペリフェラル層は通常は一時状態を先に表示します。
ただし、`STATE_BOOTLOADER` は一時状態より先に処理され、白色を出力してから移行します。
初期化エラーは定常状態として保持されますが、現行のLED処理では一時状態が残っている場合に
初期化エラー表示を先に選択しません。通常の起動経路では初期化エラーより前に一時状態が設定されないため、
この競合は通常発生しません。

## 起動時の処理

起動時は、次の順番で状態を更新します。

1. `STATE_BOOTING` を要求し、起動中であることを表示する。
2. 初期のペリフェラルを初期化する。
3. `STATE_SYS_INIT` を要求し、基本的な初期化中であることを表示する。
4. 設定を初期化する。
5. キーマトリクスと入力処理を初期化する。
6. マトリクス以外のペリフェラルを初期化する。
7. BLEが有効なら `STATE_BLE_INIT` を要求し、BLEを初期化する。
8. USB HIDを初期化する。
9. `STATE_INIT_COMPLETE` を要求し、初期化完了を表示する。
10. 初期化完了の表示を短時間維持した後、通信状態へ移行する。

設定、周辺機器、BLEの初期化に失敗した場合は、対応する `STATE_INIT_ERROR_*` を要求します。
初期化エラーでは通常運用へ進まず、エラー状態を表示し続けます。
ただし、現行の `settings_init()` は永続化領域の初期化、復元、再構築に失敗しても成功を返すため、
`STATE_INIT_ERROR_SETTINGS` へは到達しません。`main.c` には要求処理が残されています。

BLEが無効なビルドでは `STATE_BLE_INIT` を経由せず、
`STATE_SYS_INIT` から `STATE_INIT_COMPLETE` へ進みます。

## 通常運用時の状態解決

初期化完了後は、接続状況を周期的に確認して定常状態を決めます。

```text
USBがマウント済み
  -> STATE_USB_CONNECTED
USBがなく、BLEが接続済み
  -> STATE_BLE_CONNECTED
どちらも接続されていない
  -> 接続優先設定に応じた STATE_USB_WAITING または STATE_BLE_WAITING
```

USBのマウントまたはアンマウント、BLEの接続または切断を契機に状態を直接変更するのではなく、
周期処理で状態を再解決します。
これにより、通信イベントのコールバックは通信処理に集中でき、状態管理との依存を持ちません。

接続済み状態の基本LED表示は消灯です。ただし、接続済み状態でも一時状態は保持でき、
設定保存やVial操作の結果を一時的に表示できます。

## 設定更新との連携

設定更新処理は、実際に設定を変更して保存処理を行った場合、更新結果を
`settings_update_result_t` で返すと同時に、対応する一時状態を設定します。

| 設定更新結果                | 一時状態                        |
| --------------------------- | ------------------------------- |
| `SETTINGS_UPDATE_PERSISTED` | `STATE_TEMP_SETTINGS_PERSISTED` |
| `SETTINGS_UPDATE_RAM_ONLY`  | `STATE_TEMP_SETTINGS_RAM_ONLY`  |
| `SETTINGS_UPDATE_FAILED`    | `STATE_TEMP_SETTINGS_FAILED`    |

保存処理の開始時には `STATE_TEMP_SETTINGS_SAVING` を設定しますが、保存処理は同期的に実行され、
完了直後に結果状態へ置き換えられます。そのため、通常の周期処理が観測するのは結果状態であり、
`STATE_TEMP_SETTINGS_SAVING` の表示は実質的に行われません。
永続化領域が利用できない場合や保存に失敗した場合でも、RAM上の変更は保持されることがあります。
その場合は `STATE_TEMP_SETTINGS_RAM_ONLY` を設定し、再起動後に変更が失われる可能性を示します。

不正な位置やキーコードを指定した場合、またはキーマップ更新自体に失敗した場合は、
`STATE_TEMP_SETTINGS_FAILED` を設定します。
ただし、Vialキーコードを内部キーコードへ変換できなかった場合は、Vial処理が失敗応答を返すだけで
一時状態を設定しません。
変更前と同じキーコードを指定した場合や、すでに初期値へ戻っている場合は変更なしとして結果だけを返し、
一時状態は設定しません。

## Vial操作との連携

Vialのロック状態は、USBやBLEの定常状態とは別に管理されます。

- アンロック開始時に `STATE_TEMP_VIAL_UNLOCKING` を設定する。
- アンロックが完了したら `STATE_TEMP_VIAL_UNLOCKED` を設定する。
- ロック中に変更操作を受け付けなかった場合は `STATE_TEMP_VIAL_LOCKED` を設定する。
- アンロック状態を解除した場合は一時状態をクリアする。
- アンロック済みでブートローダー移行を受け付けた場合は `STATE_BOOTLOADER` を要求する。

Vial操作の状態を定常状態にしないため、USB接続中でも通信状態を維持したまま操作の進行や結果を表示できます。
ただし、`STATE_TEMP_VIAL_UNLOCKING` の表示期限は500msで、アンロックに必要な保持時間は5秒です。
そのため、現行の実装ではアンロック完了前に解除中表示が消え、完了時に完了通知が表示されます。

## LED表示への変換

LEDの表示方法はペリフェラル層が状態から解決します。
状態管理層はRGB値や点滅周期を保持しません。

定常状態の基本表示は次のとおりです。

| 状態の区分               | 表示                   |
| ------------------------ | ---------------------- |
| 起動・ブートローダー移行 | オレンジまたは白の点灯 |
| システム初期化           | 黄色の点灯             |
| BLE初期化・待機          | 水色の点灯または明滅   |
| USB待機                  | 青色の明滅             |
| 接続済み                 | 消灯                   |
| 初期化エラー             | 赤色の回数指定点滅     |
| ディープスリープ         | 消灯                   |

一時状態は、定常状態の基本表示より優先して表示できます。
設定保存開始時やVialアンロック開始時は明滅状態を設定し、操作完了やエラーは色と点滅回数で表します。
ただし、設定保存中状態は同期処理中に結果状態へ置き換えられるため、通常は明滅を観測できません。
表示の色や周期、表示時間はペリフェラル層が管理します。

`led_brightness` の設定は、点灯、明滅、点滅回数指定のすべてのパターンに適用されます。
ブートローダー移行時は、白色点灯を出力してから新しい時間変化を前提としないブートローダーへ移行します。

## 低電力状態とブートローダー

ディープスリープへ移行すると、状態管理は `STATE_DEEP_SLEEP` を現在の定常状態にします。
ペリフェラルは移行前にLEDを消灯し、スリープ処理へ進みます。
スリープ中は周期処理が停止するため、スリープへ移行した後のLED表示更新は行いません。

ブートローダー移行は、一時状態ではなく定常状態の移行要求です。
要求を受けた後は、ペリフェラルが白色点灯を出力してからブートローダーへ移行します。
そのため、移行直前の表示は、ブートローダー側でLED更新が行われなくても保持されます。

## 関連する制限

- 定常状態は直接設定せず、移行要求と周期処理を経由します。
- 一時状態は一つだけ保持され、新しい状態を設定すると以前の状態は失われます。
- 一時状態の表示期限は状態管理ではなくペリフェラル層が管理します。
- USBまたはBLEの通信イベントだけでは定常状態を変更せず、周期処理で接続状況を再評価します。
- 接続済み状態は基本表示が消灯ですが、一時状態の表示を禁止するものではありません。
- 初期化エラーは通常運用へ自動復帰せず、対応するエラー状態を表示し続けます。
  ただし、設定初期化エラーは現行の `settings_init()` の戻り値では発生しません。
- 初期化エラー状態が設定される前に一時状態が残っている場合、現行のLED処理では一時状態が優先されます。
- 設定変更なしの結果やVialキーコード変換失敗では、結果に対応する一時状態が設定されない場合があります。
- Vialアンロック中の一時状態は、アンロック完了まで保持されず、500msの表示期限でクリアされます。
- ディープスリープ中は周期処理を実行できないため、LED表示を更新できません。
- ブートローダー移行後はファームウェア側の表示更新を継続できません。

## 処理の全体像

```text
電源投入
  -> STATE_BOOTING を要求
  -> 基本周辺機器を初期化
  -> STATE_SYS_INIT を要求
  -> 設定、入力、周辺機器を初期化
      -> 失敗: STATE_INIT_ERROR_* を要求して停止
  -> BLE有効時: STATE_BLE_INIT を要求してBLEを初期化
      -> 失敗: STATE_INIT_ERROR_BLE を要求して停止
  -> STATE_INIT_COMPLETE を要求
  -> 通信状態を周期的に解決
      -> USBマウント: STATE_USB_CONNECTED
      -> BLE接続: STATE_BLE_CONNECTED
      -> 未接続: 優先設定に応じた待機状態

設定またはVial操作
  -> 一時状態を設定
  -> ペリフェラルが一時状態を表示
  -> 表示期限後に一時状態をクリア
  -> 定常状態の表示へ戻る
```
