# VIAL設定の永続化

## 概要

VIALから変更したキーマップは、キーボード本体のフラッシュメモリへ保存されます。
保存されたキーマップは、USBケーブルを抜いたり、キーボードを再起動したりしても復元されます。

この処理が対象とするのは、今のところはVIALから変更できる動的キーマップです。
ファームウェアにあらかじめ組み込まれた規定キーマップや、
VIALのすべての設定項目を保存するものではありません。

保存処理では、電源が途中で失われたことを検出できるようにしています。
途中までしか保存できなかったデータをそのまま使うことはせず、
次回起動時に保存領域を初期化して規定キーマップへ戻します。

## 保存されるデータ

フラッシュメモリには、次のデータが保存されます。

- そのファームウェアのビルドを識別する値
- 現在のキーマップを復元するための基準データ
- 基準データからの変更履歴
- 保存処理が完了したかを示す管理情報

キーマップは、ファームウェア内部で使用しているキーコードの形式で保存されます。

保存領域は他の機能が使用するフラッシュ領域と重ならないように、
ファームウェアのビルド時に配置が決まります。
保存領域の大きさは4セクタ、通常16KiBです。

## 起動時の処理

キーボードの電源を入れると、最初にファームウェアに組み込まれた規定キーマップをメモリへ読み込みます。
その後、フラッシュメモリの保存内容を確認します。

保存内容が正常な場合は、次の順でキーマップを復元します。

1. 保存されている基準データを読み込む
2. 基準データへ変更履歴を順番に適用する
3. 復元したキーマップを、動作中のキーマップとして設定する

保存内容がない場合や、次のような異常が見つかった場合は、保存内容を使用しません。

- 別のファームウェア用に保存されたデータである
- 保存処理が途中で中断されている
- 保存の進み方を示す管理情報が壊れている
- 変更履歴が途中で途切れている、または内容が不正である
- 保存されたキーマップを読み込めない

この場合は保存領域全体を消去し、現在のファームウェアの識別値と規定キーマップを保存します。
起動後は規定キーマップが使用されます。

## VIALからキーマップを変更した場合

VIALでキーコードを変更すると、次の処理が行われます。

1. VIALから受け取ったキーコードを、ファームウェア内部のキーコードへ変換する
2. 動作中のキーマップを変更する
3. 変更内容をフラッシュメモリへ保存する
4. 書き込んだ内容を読み直し、正しく保存できたことを確認する

通常の1キー変更では、現在のキーマップ全体を書き直さず、変更箇所を変更履歴として追加保存します。
このため、同じキーマップ領域を何度変更しても、後から保存された変更が優先されます。
これはフラッシュメモリの書き込み回数を節約し、寿命を延ばすためです。

変更履歴を書き込む空き容量がなくなった場合は、現在のキーマップ全体を新しい基準データとして保存し直します。
保存回数の上限に達した場合も同じ処理を行います。

変更前と変更後のキーコードが同じ場合は、キーマップもフラッシュメモリも変更しません。

## Dynamic Keymap Reset

VIALのDynamic Keymap Resetを実行すると、動作中のキーマップを規定キーマップへ戻します。

この操作はキーマップ全体を変更するため、1キー変更用の変更履歴には分解しません。
保存領域を消去し、規定キーマップを新しい基準データとして保存します。

リセット後に再起動すると、保存された規定キーマップが読み込まれます。

## 保存処理の安全性

フラッシュメモリには、保存処理の進み具合を記録する管理情報があります。
1回の保存では、次の順で状態を進めます。

1. 保存を開始したことを記録する
2. キーマップまたは変更履歴を書き込む
3. 書き込み結果を読み直して確認する
4. 保存が完了したことを記録する

保存完了の記録まで到達していない保存は、次回起動時に未完了として扱われます。
電源断やリセットが書き込みの途中で発生した場合でも、未完成のデータを復元しないための仕組みです。

チェックサムは使用していません。
代わりに各書き込みの直後にフラッシュメモリからデータを読み直し、
書き込もうとしたデータと一致するかを確認します。

## 保存に失敗した場合

フラッシュメモリの消去、書き込み、または書き込み後の確認に失敗した場合、その保存は成功として扱いません。

この場合の動作は次のとおりです。

- VIALの書き込み要求は失敗します。ただし動作中のキーマップは変更されます。
- 現在動作中のキーマップは、電源が切れるまでは変更後の状態で使用されます。
- 失敗した保存を完了済みとして記録しません
- 次回起動時には保存領域が不正と判定され、規定キーマップから再初期化されます

そのため、VIALから変更した直後に書き込み失敗が通知された場合、その変更が次回起動後も残るとは限りません。

## ファームウェア更新時の扱い

保存データには、ファームウェアのビルドを識別する値が含まれています。
この値は、ビルド準備のプロファイル生成処理が実行されるたびに、新しい16バイトの乱数として生成されます。

起動時に保存データの識別値と、実行中のファームウェアの識別値が一致しない場合は、
以前のファームウェア用のデータとして扱います。
以前のキーマップを新しいファームウェアへ引き継がず、保存領域を初期化して新しい規定キーマップを保存します。

そのため同じソースから作ったファームウェアでも、プロファイル生成をやり直した場合は以前の保存データを引き継ぎません。
これにより、ファームウェアの構造やキーコードの意味が変わった場合に、
互換性のない古いキーマップを誤って使用することを防ぎます。

## 保存回数とフラッシュの使い方

保存領域では、保存の完了回数をフラッシュの性質に合わせて管理しています。
1回の保存につき、保存開始と保存完了を示す2つの記録を使用します。

進捗を記録する領域は512バイトで、約2000回の保存に使用できます。

ただし、変更履歴の保存に必要な空き容量が先になくなる場合があります。
その場合は、保存回数を使い切る前でもキーマップ全体を基準データとして保存し直します。
保存し直した後は、保存回数を新たに数え始めます。

## VIALからの読み出し

VIALがキーマップを読み出すときは、起動時に復元されたメモリ上のキーマップを使用します。
読み出し要求のたびにフラッシュメモリへアクセスすることはありません。

そのため、VIAL上で表示されるキーマップは、現在キーボードが動作に使用しているキーマップと同じです。

## 処理の全体像

```text
電源投入
  -> 規定キーマップを読み込む
  -> フラッシュの保存内容を確認
      -> 正常: 基準データと変更履歴からキーマップを復元
      -> 異常: 保存領域を消去して規定キーマップを保存

VIALでキーを変更
  -> 動作中のキーマップを変更
  -> 変更履歴を保存
      -> 空きあり: 変更履歴を追加
      -> 空きなし: キーマップ全体を保存し直す

Dynamic Keymap Reset
  -> 規定キーマップへ戻す
  -> 保存領域を消去
  -> 規定キーマップを保存
```

## 関連する制限

- 保存領域はファームウェアのビルドごとに識別されます。
- 保存処理の途中で電源が失われた場合、変更前のデータを復元できるとは限りません。
  次回起動時は規定キーマップへ戻ることがあります。
- フラッシュメモリの書き込みに失敗した場合、VIALの変更は成功として扱われません。
